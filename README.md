# A and K さま トップページ デザイン案

株式会社 A and K さま（www.aandkcorp.com）のリニューアル用トップページ案。
構成は [aandk-proposal](https://github.com/easywebcraft/aandk-proposal) の02節・03節に合わせてある。

| 案 | 方向 | URL |
| --- | --- | --- |
| A | 明朝・広い字送り・金茶（エアロファシリティー社を参考） | https://easywebcraft.github.io/aandk-design/a/ |
| B | ゴシック・青・情報量（Sky株式会社を参考） | https://easywebcraft.github.io/aandk-design/b/ |

**ページ構成は案で変えない。**（変えると案の比較ができなくなる）
生成先は `a/` `b/` の下。`index.html` は案の入口。

### 案Bの参考値（https://www.skygroup.jp/ のCSSを読んで確認）

| | 参考サイト | 案Bでの実装 |
| --- | --- | --- |

| ボタン | 角丸のピル（問い合わせ） | 同じ |

**各ページは独立している**（提案書02節の構成に合わせた10ページ）:
`index` / `service` / `support` / `flow` / `partners` / `company` / `faq` /
`news` / `contact` / `privacy`

## 生成のしくみ

**原本は `src/plan-a.html`（1枚もの）。生成物を直接編集しないこと。**

```bash
cd ~/aandk-design && python3 build.py
```

`build.py` が原本を head・ヘッダー・ヒーロー・各節・CTA・フッターに切り分け、
節ごとに独立したページを組み立てる。メニューのリンクはアンカー（`#visas`）から
ページ（`service.html`）へ自動で張り替わり、いま見ているページには印が付く。
下層では節見出しを隠す（ページ見出しと二重になるため）。

お知らせは `src/news.json`（旧サイトから抽出した全13件）から生成する。
会社概要の表と、お問い合わせ・プライバシーポリシーの中身は `build.py` の中。

**デザインを直すときは原本と生成物を必ず一緒にコミットする**（生成物だけ
revert しても次のビルドで戻ってしまう）。

## 案Aの考え方

読み手は**受入企業の採用担当**。かみのて（保育園・放デイ）とは正反対で、
やわらかさや親しみではなく**確かさと品位**で信用を作る。

**エアロファシリティー株式会社（https://www.aero.co.jp/）のサイトを参考にしている**
（ユーザー指定）。参考にしたのは書体・配色・余白の取り方・レイアウトの型で、
**CSSは自前で書いている**（先方のCSSやサブセットフォントは使わない）。

| 要素 | 参考サイト | 案Aでの実装 |
| --- | --- | --- |
| 見出しの書体 | Source Han Serif Light（自社ホストのサブセット） | **Noto Serif JP**（同じ源ノ明朝。Google Fonts） |
| 本文の書体 | 游ゴシック系 | 同じ |
| 差し色 | `#b39861`（金茶） | 同じ |
| ヘッダー | 2段・ロゴ中央・ナビ左右振り分け・上段に対象者別リンク | 同じ型 |
| ヒーロー | 全幅写真＋右下に明朝の欧文＋和文コピー | 同じ型 |
| お知らせ | ヒーロー下端に半透明の帯を重ねる | 同じ型 |
| ボタン | 平行四辺形（skew） | 同じ（中身を逆skewして文字はまっすぐ） |

字送りを広く取る（見出し `.14〜.22em`）のが、この方向のいちばんの肝。

## ハマった点

- **社名と添え書きを `<span>` のままにしてインラインで流れ、ナビに重なった**。
  `.brand .txt` を flex-column にし、`.nm`/`.sub` を block にする。電話番号も同じ。
- **ヘッダーを畳む幅は 1080px**。畳む指定はレイアウトの折返し（1000px）と
  **別の @media に分ける**。まとめると中間の幅が意図せず1カラムになる。
- **ロゴは幅186px。** 112pxだと `logo.png`（400×78の横長ロックアップ）の
  社名が読めない。参考サイトのロゴは縦組みなので同じ寸法では通らない。
- **★ヒーローの文字の可読性は、要素の実座標を取ってから測ること。**
  目分量のy座標で測って「2.92:1で不足」と誤診した。右寄せの文字なので、
  文字の無い左半分を測っていたのが原因。`kmtest/_ak_rect.html` で
  `getBoundingClientRect` を出させてから、その矩形だけを測る。
  実測値＝欧文 10.58:1／和文 12.49:1（どちらも白文字・WCAG AA以上）。

## 検査

390 / 600 / 768 / 1020 / 1021 / 1200 / 1440px で横あふれなしを確認済み。

## お知らせの引き継ぎ

旧サイトの `/news` は **1ページに全件が並ぶ作り**（ページ送りも記事個別ページも無い）。
記事は「日付だけの行で始まる `<p>`」＋その後ろのギャラリー、という構造。

抜き出しの注意:
- **同じ記事が2回出てくることがある**（2020.05.25 と 2019.09.06）。日付＋見出しで重複を除く
- 日付の表記が `2021/8/30` と `2021年3月28日（日）` の2種類ある
- 本文に `<wbr>` が挟まっているので、タグを剥がしてから結合する
- 画像は `/application/files/...` の絶対パス。`http://aandkcorp.com` を前置いて取得する

`news.html` は `plan-a.html` の `<head>`〜`</style>`・ヘッダー・フッターを
そのまま流用して組み立てている。**案Aのデザインを変えたら news.html も作り直すこと。**

## 明るさの調整（2026-09-06）

ユーザーの「暗いイメージ」への対応。**測ってから直した**＝最初の1画面を撮り、
画素ごとの相対輝度から「暗い画素（輝度0.18未満）の割合」を出す。

| | 適用前 | 適用後 |
| --- | --- | --- |
| 1画面の平均の明るさ | 28.9% | **58.9%** |
| 暗い画素の割合 | 68.3% | **32.3%** |

直したのは5点:
1. **お知らせの帯を濃紺のベタ→クリーム地**（この帯だけで暗い画素96%だった）
2. **ヒーローのかぶせを、全面の幕から文字の後ろだけの楕円に**
3. 写真そのものを×1.18で明るく焼いた（`brighten.sh`。CSSの `filter` は
   スクロールのたびに効いて重いので使わない）
4. **下部のCTAも濃紺のベタ→クリーム地＋金茶のボタン**
5. ヒーローの高さ 62vh → 50vh

**★楕円の中心は見出しの高さに置くこと。** 最初 76% に置いたら、いちばん大きい
「A and K」の背後が薄いままで **3.71:1** まで落ちた。62% に上げて **7.28:1**。
和文は 15.92:1。**明るくしたあとは必ず測り直す。**

参考にしたエアロファシリティー社は夕日の空という明るい写真なので、同じ構造でも
印象が逆に出ていた。写真が室内・蛍光灯である以上、上の5点は「今の写真をどう
見せるか」の調整。さらに明るくしたいときは写真自体を替えるしかない。

## ヒーローを空の写真にした（2026-09-06）

ユーザー指示。実習生の教室写真は室内・蛍光灯で、明るさの調整だけでは限界があった。

**★明るい写真に白文字は成立しない。** 白文字を成立させるには背景を暗くするしかなく、
それは「明るくしたい」という目的と正面から矛盾する。**文字を濃紺（--navy）にして、
かぶせを外した。**

ただし空は青いぶん、濃紺の文字でも **3.15:1** しか出ない（実測）。全面に白を
かぶせると写真の色が抜けて牛乳をかけたようになるので、**文字の当たる楕円だけを
白く起こした**（局所の白）。結果 **見出し 9.89:1 ／ 和文 11.34:1**。

| | 教室の写真 | 空の写真 |
| --- | --- | --- |
| 1画面の平均の明るさ | 58.9% | **81.3%** |
| 暗い画素の割合 | 32.3% | **0.5%** |

写真は Unsplash（`mOoHf5-ZnWE`）。ライセンスの懸念はないが、**実写真が届いたら
差し替える前提の仮素材**。教室の写真は提携機関の節でそのまま使い続けている。

## スマホのメニュー（2026-09-06）

**ハンバーガーのボタンだけ置いて、開くメニューもJSも書いていなかった**
（押しても何も起きない状態でユーザーから指摘）。かみのてで同じことを一度
やっているので、次は最初から実装すること。

- **ボタンの真下に開くドロップダウン**にした。**全画面のパネルにしないこと**
  （かみのてで一度作って戻した。画面を覆うと閉じ方が分からないと言われる）
- 閉じる操作は3通り＝項目を選ぶ／外側を押す／Escを押す
- `aria-expanded` と `aria-label` を切り替える
- **PCで隠している上段の対象者別リンクも、ここに入れる**（スマホでは
  `.utility .seg` が display:none になり、入口が消えてしまうため）

検査は `kmtest/_ak_menu.html`（開閉の動作）と `_ak_menuall.html`（10ページ分）。
**★リンクの click をそのまま呼ぶとiframeが遷移して load が再発火し、無限に
回ってEdgeが固まる。** capture フェーズで preventDefault し、`load` は1回だけ
処理すること。
